# Deploying AgroLink: Vercel (frontend) + Render (backend) + MongoDB Atlas (database)

```
Browser ──► Vercel   (React, static files)                 https://agrolink.vercel.app
   │
   └──────► Render   (Spring Boot in a Docker container)   https://agrolink-backend.onrender.com/api/...
                │
                └──► MongoDB Atlas (M0 free cluster)       mongodb+srv://...
```

The browser talks to both. The frontend calls the backend directly, so the backend must allow the Vercel origin (CORS).
Render has no managed MongoDB, so the database is MongoDB Atlas.

| You need an account at | For | Cost to start |
|---|---|---|
| GitHub | source of truth; Render and Vercel deploy from it | free |
| MongoDB Atlas | database | free (M0, 512 MB) |
| Render | backend | free, with limits (see below) |
| Vercel | frontend | free (Hobby) |
| Razorpay | payments | free in test mode |

Names used below (`agrolink-backend`, `agrolink`) are examples. If Render or Vercel gives you a different URL, use that one everywhere.

---

## 0. Before you start

1. Push the repository to GitHub. The repo root must contain `backend/`, `frontend/`, `render.yaml`.
2. **Rotate old secrets.** The Razorpay test secret, the JWT secret and the database password from the microservice
   version are in git history. Create fresh ones for this deployment and never reuse the old ones.
3. Decide a region. `render.yaml` uses **Singapore**; pick the Atlas region nearest to it (AWS Singapore or Mumbai).
   Change `region:` in `render.yaml` if you want another (Oregon, Ohio, Virginia, Frankfurt, Singapore).

---

## 1. MongoDB Atlas (database)

1. Create a project and a **free M0 cluster** (AWS, Singapore or Mumbai).
2. **Database Access → Add user**: username `agrolink`, a long random password, role **Read and write to any database**
   (or `readWrite` on the `agrolink` database). Avoid `@ : / ? # %` in the password, or URL-encode them in the URI.
3. **Network Access → Add IP address → `0.0.0.0/0`**. Render's free instances do not have one fixed IP, so Atlas has to
   accept connections from anywhere. The strong password is what protects the database; do not skip it.
4. **Connect → Drivers** and copy the connection string. Put the database name `agrolink` after the host:

```
mongodb+srv://agrolink:<PASSWORD>@cluster0.abcde.mongodb.net/agrolink?retryWrites=true&w=majority
```

The app creates its collections and indexes (unique `username`, cart `userId`) on first start.
Photos are stored in MongoDB as well, so Render needs no disk. Watch the 512 MB M0 limit if you upload many images.

## 2. Render (backend)

Java is not a native Render runtime, so the backend runs from [`backend/Dockerfile`](backend/Dockerfile).

### Option A: Blueprint (recommended)

1. Render dashboard → **New → Blueprint** → connect the GitHub repository. Render reads [`render.yaml`](render.yaml).
2. Fill in the prompted values from the table below. `JWT_SECRET` is generated for you.
3. **Apply**. The first build takes several minutes (Maven downloads dependencies).

### Option B: by hand

**New → Web Service** → your repo → **Runtime: Docker**, **Dockerfile path** `./backend/Dockerfile`,
**Docker build context** `./backend`, **Health check path** `/actuator/health`, instance type **Free**, then add the
environment variables below.

### Backend environment variables (Render → service → Environment)

| Key | Required | Value | Notes |
|---|---|---|---|
| `MONGODB_URI` | yes | `mongodb+srv://agrolink:<PASSWORD>@cluster0.abcde.mongodb.net/agrolink?retryWrites=true&w=majority` | From step 1. Must include `/agrolink`. |
| `JWT_SECRET` | yes | *generated by the Blueprint*, or run `openssl rand -base64 48` | At least 32 bytes. If it is missing the app starts with a public dev key, so never leave it unset. Changing it logs everyone out. |
| `CORS_ALLOWED_ORIGINS` | yes | `https://agrolink.vercel.app` | Exact frontend origin, no trailing slash, no path. Several allowed, comma-separated. |
| `ADMIN_USERNAME` | first deploy | `agrolink-admin` | Creates this ADMIN account at startup if it does not exist. Public sign-up cannot create admins. |
| `ADMIN_PASSWORD` | first deploy | a strong password, 12+ characters | After you have logged in once you can delete this variable; the account stays. |
| `ADMIN_EMAIL` | first deploy | `you@example.com` | |
| `RAZORPAY_KEY` | for payments | `rzp_test_xxxxxxxxxxxxxx` | Dashboard → Account & Settings → API keys (Test mode). Live keys need Razorpay KYC. |
| `RAZORPAY_SECRET` | for payments | *the matching key secret* | Without the pair, the app runs and payment endpoints answer 503. |
| `DEMO_LOGIN_ENABLED` | no | `false` | Keep `false` for real use. `true` creates dummy accounts (including an admin) whose passwords are shown on the login page, and adds passwordless login endpoints. Only for a throw-away demo site. |
| `MAIL_USERNAME` | optional | `yourname@gmail.com` | See the email warning below. |
| `MAIL_PASSWORD` | optional | a 16-character Gmail **app password** | Google account → Security → 2-Step Verification → App passwords. Not your normal password. |
| `MAIL_HOST` / `MAIL_PORT` | optional | `smtp.gmail.com` / `587` | These are the defaults; only set them for another provider. |
| `JAVA_OPTS` | optional | `-XX:MaxRAMPercentage=70 -XX:+UseSerialGC` | The image default. Raise the percentage on a larger instance. |
| `PORT` | no | *set by Render (10000)* | The app already listens on it. Do not set it yourself. |

**Email warning.** Render's free web services cannot open outbound connections on ports 25, 465 or 587 (Render docs), so
Gmail SMTP will not work on the free plan. The app copes: a failed email is logged as a warning and never fails an
order or payment. To get real emails, either move the service to a paid instance, or switch the notification code to an
HTTPS email API (Resend, Brevo, SendGrid); that is a code change and is not done yet.

### Check the backend

```bash
curl https://agrolink-backend.onrender.com/actuator/health          # {"status":"UP"}
curl -i https://agrolink-backend.onrender.com/api/products          # 200 and []
```

The first request after idle time can take 30-60 s (see "Free plan limits").

## 3. Vercel (frontend)

1. Vercel → **Add New → Project** → import the same GitHub repository.
2. Settings on the import screen:

| Setting | Value |
|---|---|
| Framework Preset | Vite (detected automatically) |
| **Root Directory** | `frontend` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | default (`npm install`) |
| Node.js Version (Project Settings → General) | **22.x** (Vite 7 needs Node 20.19 or newer) |

3. **Environment Variables** (add for Production, and Preview if you use preview deployments):

| Key | Value | Notes |
|---|---|---|
| `VITE_API_BASE_URL` | `https://agrolink-backend.onrender.com/api` | The Render URL **plus `/api`**. It is baked in at build time, so after changing it you must **redeploy**. |

That is the only frontend variable. Razorpay's public key id is sent by the backend at checkout, so it is not needed here.

4. **Deploy.** [`frontend/vercel.json`](frontend/vercel.json) makes deep links such as `/products/123` and `/cart` work
   after a refresh (client-side routing).

## 4. Connect the two (order matters)

The backend needs the Vercel URL for CORS, and the frontend needs the Render URL. Break the loop like this:

1. Deploy Render first with `CORS_ALLOWED_ORIGINS=http://localhost:5173`. Note its URL.
2. Deploy Vercel with `VITE_API_BASE_URL=<render url>/api`. Note its URL.
3. Go back to Render, set `CORS_ALLOWED_ORIGINS=<vercel url>`, and let it redeploy.

Vercel *preview* deployments have their own URLs (`agrolink-git-branch-team.vercel.app`) and will be blocked by CORS
unless you add them to `CORS_ALLOWED_ORIGINS` as well. Custom domains work the same way: add the domain to that list.

## 5. Smoke test after deploying

1. Open the Vercel URL; the landing page loads. Refresh on `/login`; it should still load (no 404).
2. Register a **Farmer** account. Registering as Admin or Manager must be refused.
3. Log in with `ADMIN_USERNAME` / `ADMIN_PASSWORD`, then call `GET /api/admin/users` (or open the admin tools).
4. As the farmer, create a product with a photo; as a buyer, see it in the list, add it to the cart.
5. Payment (test mode): "Proceed to Buy" opens Razorpay Checkout. Razorpay's test card is `4111 1111 1111 1111` with any
   future expiry and any CVV. After paying, the order should show `PAID` in `GET /api/orders`.
6. In the browser dev tools, no request should fail with a CORS error. If one does, see the table below.

## 6. Free plan limits to know about

- **Render free instances spin down after 15 minutes without traffic.** The next visit waits for a cold start
  (roughly a minute). The frontend shows a "Waking up the server" page during that wait (`BackendGate`: it polls
  `/actuator/health` and continues by itself), so visitors see progress instead of errors. A free uptime pinger (UptimeRobot, cron-job.org) hitting `/actuator/health` every 5-10 minutes
  keeps it awake. Free services get 750 instance hours per month, which covers one always-on service.
- **Memory.** A free instance is small (Render's published figure is 512 MB; check their pricing page). The Docker image
  caps the JVM at 70% of available memory. If the service is killed for running out of memory, move to a paid instance
  or lower `JAVA_OPTS` heap use.
- **Atlas M0** is 512 MB of storage, shared. Product photos are stored inside it.
- **Vercel Hobby** is meant for personal, non-commercial projects; check Vercel's terms before running a real marketplace on it.

## 7. Updating, rolling back

- Both platforms deploy automatically when you push to the connected branch (`autoDeployTrigger: commit` on Render).
- Rollback: Render → service → **Events / Deploys → Rollback**; Vercel → **Deployments → Promote a previous deployment**.
- Changing a backend variable restarts the service; changing `VITE_API_BASE_URL` needs a new Vercel deployment.
- Run the tests before pushing: `cd backend && mvn test`.

---

## 8. Security checklist

- [ ] `DEMO_LOGIN_ENABLED` is `false` (or unset) in production.
- [ ] `JWT_SECRET` is a fresh random value (not the dev default, not the old committed one).
- [ ] Razorpay and database credentials are new, not the ones from the old repository history.
- [ ] `CORS_ALLOWED_ORIGINS` lists only your real frontend origins (no `*`, no localhost in production).
- [ ] Atlas user has only the access it needs and a long password; `0.0.0.0/0` is in the allow list only because Render's IPs change.
- [ ] `ADMIN_PASSWORD` removed from Render after the first successful admin login.
- [ ] `.env` files and secrets are not committed (`.gitignore` already excludes them).

## 9. Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| Browser console: *blocked by CORS policy* | `CORS_ALLOWED_ORIGINS` does not exactly match the page origin (scheme, host, no trailing slash, no path). Fix it in Render and wait for the restart. |
| Frontend shows network errors / calls `/api` on the Vercel domain | `VITE_API_BASE_URL` is missing or was added after the build. Set it and **redeploy** Vercel. |
| Refreshing `/products/123` gives a Vercel 404 | `frontend/vercel.json` is missing, or the Root Directory is not `frontend`. |
| Render build fails on `COPY target/agrolink-*.jar` | The Maven step failed earlier; read the build log above that line. |
| Render deploy is "unhealthy", logs show `MongoTimeoutException` | Atlas Network Access does not allow Render, the password is wrong or needs URL-encoding, or `/agrolink` is missing from the URI. |
| Login works, then every call is 401 after a redeploy | `JWT_SECRET` changed. Log in again. |
| Payment endpoints answer 503 "not configured" | `RAZORPAY_KEY` / `RAZORPAY_SECRET` missing, or only one of the pair is set. |
| Payment succeeds in Razorpay but the order stays `PENDING` | The verify call failed (check the browser network tab for `/orders/{id}/verify`); an unpaid order is released after 30 minutes. |
| Emails never arrive | Expected on Render's free plan (SMTP ports blocked); see the email warning above. |
| First request after a while is very slow | Free instance cold start; use an uptime pinger or a paid instance. |
